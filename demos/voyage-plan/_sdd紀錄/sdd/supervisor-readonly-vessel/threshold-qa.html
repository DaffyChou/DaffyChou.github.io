航行監控與警示 · 三個核心問題

閾值對船還是對人

每一題分兩欄：左邊給使用者看（畫面上會看到什麼），右邊給 SA／工程師看（資料與規則怎麼定）。截圖來自 merged 版示意介面，船名與數值皆為假資料。

v1.1 · 2026-09-18（持續時間開放單船層、徽章靠左）對應規範：閾值分層規則與判斷流程摯陞數位科技 SLAB

Q1閾值的設定是對船還是對人？威明輪的監管人員有 6 位，每位看到的設定是一樣的，還是各自看到自己所設的？

對船。6 位監管看到的是同一份設定；誰改的、何時改的會標在旁邊，但值只有一份。

使用者畫面

組員 A 為 YM WARRANTY（代替威明輪）的海上航段把航線偏移 W 改成 1.2 並儲存後，維度列顯示「★ 已調整 · 海上航段 · 監管 A·呂船長 · 時間」（下圖 1）。

換主管登入、打開同一艘船，看到的是一模一樣的值與徽章，設定者仍顯示監管 A（下圖 2）。若還有第 2～6 位監管，他們看到的也是這一份；任何人再改，值就被取代、設定者換成他。

SA／工程說明

閾值資料的 key 是 vessel_id × dimension × segment，沒有 user 維度。四層資料結構都以船或船隊為對象：

L4 全船隊預設 _thresholds[dim]（含 .seg[航段]）
L2 單船常設 _vesselOverrides[vid][dim].seg[航段]
L1 時效單船 _temporalOverrides[vid][]
圍籬單船層 _zoneIoVesselCfg[vid][zoneId]

「人」只出現在兩個地方：每筆設定的 by / at（設定者與時間，供顯示與稽核），以及帳號的可見範圍（vessel.manager 決定組員看得到哪些船）。多位監管同管一船時採「後寫者覆蓋」，前值保留在變更紀錄。

「對人」的只有通知方式（Q8）與關注船舶（Q11），都與閾值資料分開。

Q2承上，如果閾值設定是對人，主管看到的閾值會是？

因為是對船，主管看到的和組員完全相同；主管多的是「看全部船、看所有組員設了什麼」的視角，不是另一份值。

使用者畫面

主管在單船設定頁用「組員」下拉選監管 A，「覆寫總覽」列出 A 所有船的個別設定：船名、維度、航段、層級、閾值、設定者·時間。點任一列直接跳到那艘船（下圖 3）。

切到「分航段集體設定 › 全船隊預設」，主管看到的是船隊基準值（此例航線偏移 W 1.5 / C 3）——這是所有沒有個別設定的船在用的值，也是組員畫面「預設」欄顯示的來源（下圖 4）。

如果主管從來沒設過，這個值其實是系統預設（原廠值）：頁首會提示「N 個維度尚未設定，目前為系統預設」，徽章是灰色虛線的「系統預設·通用」（下圖 4a、4b）；主管設過之後才變成「全船隊」。維度名稱後的小 ⓘ 點了顯示該值的依據（見 §預設值依據）。

SA／工程說明

主管與組員呼叫同一個解析器 getEffectiveThreshold(dim, vessel)，回傳值與來源不因登入者而異。差別只在權限碼：

組員 threshold.vessel.edit.own（只能改指派給自己的船）；主管另有 threshold.fleet.edit、threshold.vessel.edit.any、audit.view.all、vessel.view.all。

L4 通用格是否「曾被設定」由 globalAllSet(dim) 判定（有 by 設定者記錄，或值與 DEFAULT_THRESHOLDS 不同）；未設定時解析器的來源回 system（不再併入 global），徽章樣式 th-src-system。依據文字集中在 DEFAULT_THRESHOLD_BASIS。

「覆寫總覽」是對 _vesselOverrides 與 _temporalOverrides 依 vessel.manager 篩選後的唯讀彙整；「全船隊預設」分頁直接編輯 L4。若未來真的需要「對人」的設定（例如每人不同的通知門檻），應另開個人偏好表，不要混進閾值分層，否則主管與組員會看到不同的警報結果、無法對帳。

Q3如果主管在「分航段集體設定 › 全船隊預設」修改了航線偏移，所有監管人員的所有船的航線偏移都會被更動嗎？

沒有個別設定的船會全部跟著變；已有單船／時效／區域設定的船不受影響。套用前確認框會告訴主管各有幾艘。主管沒有清除組員設定的按鈕；要讓那些船跟上，請組員自己「復原」。

使用者畫面

主管把全船隊預設的海上航段航線偏移 W 改為 0.8，按「套用變更」，確認框列出影響船數與不受影響的船數：

系統確認框（實際文字）
即將寫入全船隊預設（L4）· 海上航段
・航線偏移：W 沿用 → 0.8 NM、C 沿用 → 沿用
　影響 8 艘（目前處於海上航段 5 艘）；1 艘有單船／時效／區域覆寫，不受影響

變更於下一輪資料週期生效；有覆寫的船不會跟著改，需另行「清除覆寫」。

確認套用？

套用後，監管 A 個別設過的 YM WARRANTY 仍是 1.2（徽章「單船·海上航段」；「預設」欄顯示新的 0.8 只是提示，並未生效）（下圖 5）；監管 B 沒設過的 YM MILESTONE 則直接跟著變成 0.8（徽章「全船隊·海上航段」）（下圖 6）。兩個動作都留在變更紀錄（下圖 7）。

SA／工程說明

寫入 L4 只改 _thresholds.route.seg.sea.warning 一個欄位，不碰任何 L1～L3 資料。生效值是每一輪資料更新時由解析器逐船算出：有 L2／L1 的船命中上層就停，L4 的變更被「遮蔽」；沒有的船落到 L4 才會拿到新值。

影響預覽 fleetImpactSummary(dim, seg)：對全部船跑一次解析器，W 與 C 兩個欄位的來源都不是 global 者計為「不受影響」；同時統計目前處於該航段的船數（本例 5 艘），因為海上航段專屬值只在船處於海上時生效。

正式系統不需要在儲存時重算全船隊；閾值只是比較參數，下一輪 AIS／氣象輪詢自然套用。L4 寫入時不會自動刪除下層資料——那會讓組員的設定無聲消失，且無法稽核。

客戶 9/16 確認（選項 C）：主管完全不能清除組員的覆寫。權限碼 threshold.vessel.clear.own 只給組員（代理人經授權亦可），主管沒有 .any 版本；canClearVessel(v) 為 false 時，單船頁的「清除此航段所有設定」、每列「復原」、時效「移除」、圍籬「清除覆寫」全部不渲染，處理函式亦各自拒絕；集體設定「依監管人員的船隊」範圍下 batchResetAllowed() 為 false，只剩「套用變更」。主管仍可改值、新增時效覆寫、停用此船（設定者記為主管）。「全船隊預設」的「清除此航段所有設定」保留，只把 L4 重置回系統預設。

Q4組員請假時，代理人能不能改他的船的閾值？誰能授權、多久？

能，但要有授權。授權者本人或該部門主管建立授權（代理人、船舶範圍、期限上限 30 天、事由），有效期間內代理人可編輯，設定者記為「代理人（代 授權者）」。

使用者畫面

組員 A 在警示設定頁上方的「代理授權」面板按「＋ 新增授權」，在對話框建立授權給 B（下圖 8）。面板只有一張表，組員只看到與自己有關的列，主管看全部門；規則說明收在「ⓘ 規則」。B 的右上角「代理檢視」變為可勾並顯示可代管船數，閾值頁船舶下拉多出 A 的船、標「代理 · 監管 A」（下圖 9）。B 儲存後，該列設定者顯示「監管 B（代 監管 A）」（下圖 10）。

B 看到同一張表裡「監管 A → 我」那一列，沒有撤銷鈕；主管的表列出全部門授權，可代任何組員建立與撤銷（下圖 11）。

SA／工程說明

授權表 proxy_grant { id, grantor, grantee, vesselScope: 'all' | [vessel_id], from, to, reason, createdBy, revokedAt? }；有效＝from ≤ now ≤ to 且未撤銷；建立時驗證 grantor ≠ grantee、事由必填、迄 > 起、期限 ≤ 30 天、部分範圍須為 grantor 名下船。

權限判斷 canEditVessel(v) = 自己的船 ∨ 主管 ∨ grantCoveringVessel(user, v)；管理授權的權限 = grantor 本人 ∨ 主管。可見範圍 vesselVisible 在勾代理檢視時只加入授權涵蓋的船，不再是全部船。

寫入時 by 與變更紀錄的 who 由 actorLabelFor(v) 決定，並附 grantId；到期由掃描標記並寫 by system 紀錄；撤銷立即失效，已寫入的值不回滾（要回滾請用「復原」）。同一船允許多筆有效授權，取最晚到期者顯示。

Q5有期限的臨時調整（軍演、颱風）要在哪裡設？

就在那個維度列裡。按列標頭右側的「限期」小按鈕在同列展開，填 W／C、起迄、事由即可；沒有限期時「有效期間」行不顯示（＝長期使用），有生效或排定的限期才自動展開並標「時效」。主管在集體設定「全船隊預設」也有同樣的「＋ 限期」，是全船隊層的限期（優先於全船隊常設、低於區域與單船層，徽章「全船隊限期·○○」）。

使用者畫面

不再有獨立的「時效性覆寫」區塊，平時列裡也看不到限期相關文字（2026-09-17 減量）。新增後徽章變「時效·○○」，該行改顯示「限期 至 … · 事由 · 到期後回 ○○ W／C」；到期自動失效、收進「已到期 N 筆」。同一維度同時只允許一筆限期，期間重疊會被擋下（下圖 12、13）。主管看得到、可新增，沒有「移除」。

SA／工程說明

資料仍是 L1 _temporalOverrides[vid][]，解析順序 L1 > L2 不變；全船隊限期另存 _fleetTemporal[]（來源 fleetTemporal），解析器插在區域之後、全船隊常設之前；只是渲染改為 temporalInlineHTML(v, dim, seg) 掛在 dimRowHTML 的 extraContent。「到期後回」用 getEffectiveThreshold(dim, v, hits, { skipTemporal: true }) 算，與實際計算同一解析器。新增時檢查同維度×航段的 active／pending 期間是否重疊（from < newTo && to > newFrom）。

Q7到離區域監控的圍籬誰能管？怎麼分組？能不能刪？也有分層嗎？

有權限的人（主管或組員）都能新增、編輯圍籬與分組；圍籬不可刪除、只能停用；圍籬也走 L1 > L2 > L4，單船為最高權限——船隊層停用時本船仍可自行啟用。

使用者畫面

閾值頁的圍籬列表依「組名」分節，繪製時沒填組名就是「未分組」；組名列右側的鉛筆／垃圾桶圖示可改名、刪除組（圍籬回未分組），工具列「＋ 分組」，拖曳列首「⋮⋮」到其他組名列即可換組（小螢幕改用下拉），勾選多列可「移至分組」。不用的圍籬按「停用」，停用的預設不列出，工具列「顯示已停用（M）」開了才以灰階顯示；圍籬沒有刪除功能（下圖 14）。

單船設定頁對每個圍籬可以：勾掉或勾回「是否監控」（只對本船；船隊層停用時勾回＝只對本船啟用，標「本船啟用」）、開關與改到達／離開提醒距離（標「單船」）、按「限期」在同列下方設有期限的調整（限期停用或限期啟用），名稱旁出現「時效」，到期自動恢復（下圖 15）。

SA／工程說明

分組：USER_ZONE_GROUPS（首項恆為 UNGROUPED）、addUserZoneGroup / renameUserZoneGroup / deleteUserZoneGroup / setUserZoneGroup，皆寫 layer=fence 紀錄。列表依 z.group 分節，收合與搜尋沿用原 data-cat 機制（值改為組名）。

停用隱藏：列帶 data-disabled，is-disabled-hidden 由 session 旗標 slab_va_zoneio_show_disabled 與搜尋命中決定；全部啟用／停用與全選只作用於可見列。介面不提供刪除（deleteUserZone 僅供程式清理）。

分層：L4 _zoneIoFenceConfig → L2 _zoneIoVesselCfg（disabled／forceOn／arriveOn／arriveNm／departOn／departNm；forceOn＝船隊停用時仍啟用）→ L1 _zoneIoVesselTmp（同欄位＋from／to／reason），getZoneIoFenceCfg(zoneId, vid) 依序套用，回傳 temporal 供徽章。L3「區域」對圍籬不適用。同圍籬×船同時只允許一筆限期；sweepZoneIoVesselTmp 到期標記並寫 system 紀錄。

Q8Mail／LINE 通知方式是對船隊統一設定，還是每個人自己決定？關掉通知會不會就不偵測了？

對人。每位主管、組員、代理人各自決定自己收不收；預設全開；關掉只是「不通知我」，偵測與事件完全不受影響，所以不需要另設「關閉偵測」。

使用者畫面

通知設定預設收合（2026-09-17 減量）：頁面標題列右側一個「🔔 我的通知」按鈕（整頁只有一個，不隨航段分頁重複），點開才在標題下出現「統一設定：Mail／LINE」與一句說明，有維度自訂時按鈕顯示「· N 自訂」（下圖 16）。每個維度列標頭右側有一個小 🔔：全開是一般色、有管道關閉時半透明、已自訂時帶色加圓點；點它才展開該列的「我的通知」，與統一不同時標「已自訂」並可「沿用統一」（下圖 17）。點列外或按 Esc 收合。至少要留一種管道，兩個都取消會被擋。

事件詳情多一行「通知 ＜監管人＞：Mail／LINE · 依收件人的『我的通知方式』」，讓查看者知道這筆事件是用哪些管道通知負責人的；若負責人全關則顯示「已關閉通知，僅畫面顯示」。

SA／工程說明

資料 _userNotify[user] = { all:{mail,line}, dims:{[dim]:{mail,line}} }（key slab_va_user_notify_v1），effectiveNotifyFor(user, dim)：dims 有該維度即用之，否則用 all，都沒有即全開。每維度只保存「與統一不同」的部分（勾成與統一相同時自動刪除該筆）。

寫入走 setUserNotifyAll / setUserNotifyDim，變更紀錄 layer=notify、scope=本人，不影響他人；沒有全船隊通知層，也不進四層閾值解析。通知發送時以事件的 vessel.manager（及有效代理人）逐人查 effectiveNotifyFor 決定管道。

Q9船 AIS 變成錨泊（nav_status 1）但監管人員來不及設漂航圈／錨泊位置，這段時間怎麼辦？預設值誰定？

先用全船隊預設自動監控，並提醒監管人員確認。圈心取切入錨泊那一刻的船位，半徑用主管設定的全船隊預設（未設則系統預設：錨泊 W 0.15／C 0.30 NM、漂航 W 10／C 20 NM）；監管人員之後「確認」或「調整」，未確認前徽章標「待確認」。

使用者畫面

集體設定「錨泊／漂流」分頁與其他維度列同一版型（下圖 18）：「自動套用」列（開關、預設模式、圈心取法）、「錨泊圈」列與「漂航圈」列各有 W／C 與預設值、持續分鐘與「我的通知」；修改後同樣走頁尾「套用變更」與確認框；主管可改、組員唯讀，提示列顯示「目前 N 艘自動監控中」。

單船設定頁對自動監控中的船，最上方有一塊虛線框「目前依全船隊預設自動監控（模式 · 圈心 · W／C · 自何時）」，並註明待確認提醒已用哪些管道通知監管人員；「確認（寫成本船設定）」把快照寫成常設，「調整…」跳到手動設定（下圖 19）。地圖上自動圈為虛線、事件與看板文字為「待確認（已依預設監控）」。

Q10閾值頁文字太多，哪些被收起來了？平常畫面剩什麼？

Q11主管能不能改組員船上的設定？主管有沒有自己的設定？想特別盯某幾艘船怎麼辦？

主管只看不改；主管自己的設定就是全船隊那一層；要盯船用「關注」。

使用者畫面

主管開單船設定頁選任何一艘船，標頭顯示「唯讀 · 由 ○○ 設定」，數值只顯示不能改，沒有儲存列、限期表單、圍籬開關與錨泊「確認／調整」；漂航圈／錨位按鈕變成「查看」，開出來的視窗欄位鎖住（下圖 23）。集體設定只剩「全船隊預設」，沒有「依監管人員的船隊」。

船隊監控每列船名旁有 ☆，點成 ★ 就是關注：關注船排最前，篩選多一個「★ 我的關注」；單船設定的船舶下拉把關注船列在「★ 關注」群組；該船的事件詳情會多列「★ 主管：Mail／LINE」，表示也通知了主管（下圖 24）。組員也能用關注，各自一份。

§預設值依據

「系統預設 ⓘ」滑過即顯示下列依據。這些是業界慣例與相關規範的建議來源，數值本身為 Demo 假設，上線前請依公司 SMS（安全管理系統）或船隊營運手冊確認後寫入全船隊預設並記錄設定者。

維度Demo 預設建議依據
航線偏移W 1.5／C 3 NMIMO Res. A.893(21) 航行計畫指南要求為每段航線訂 XTD（cross-track）安全限值；業界常以 Safety Frame 的 50%／100% 作 W／C。船舶上報的航線計畫若帶有建議值，另以「計畫」標示供參考。
速度異常W 20%／C 40%租約（charter party）速度條款與 Noon Report 慣例：偏離配速 10–20% 即需說明；本值為營運端經驗值，非法規。
海氣象預警W 0.65／C 0.85（海況指數）對應 StormGeo／WMO 海況等級與公司「重風險天氣迴避」內規（例：顯著波高 4 m／6 m、蒲福風級 7／9），指數化後由公司對照。
主機異常W 78／C 93（分數）依主機廠商 OEM 警戒值（RPM、排氣溫度、滑油壓）與 PMS 規範；分數為 Demo 抽象值，正式需對接輪機資料。
漂航圈半徑W 10／C 20 NM拖錨判定慣例：迴旋半徑 ≈ 船長 ＋ 出鏈長度（水深 × 3–5 倍）；W 取迴旋圈外緣、C 取其 1.5–2 倍。參考 IMO 錨泊操作指引與船長常規。
到離港W 5／C 0.5 NM以港區界線／引水登船點距離為準（各港不同）：W 為預先通報距離、C 為進入港界。
到離區域到達提醒 5 NM依 NAVTEX／NOTAM 警戒區慣例，接近邊界前 N 海浬預警；軍演區以公告範圍為準。
持續時間W 60／C 3 分AIS 回報週期（航行中 2–10 秒、慢速 3 分）與位置抖動：Warning 需持續一段時間避免瞬時尖峰誤報，Critical 較短以利即時處置。
三題背後是同一條規則：越針對這艘船、越針對此刻的設定越優先；沒設的往上一層找；主管與組員只是權限不同，看的是同一份資料。
