閾值分層規則與判斷流程

給船舶管理部門主管、組員與工程團隊的共同依據：閾值有哪幾層、哪一層優先、誰能改哪一層、改了影響誰，以及最小可行的介面流程。先定規則，再動示意介面。

版本 v0.1 · 2026-09-09摯陞數位科技 SLAB對應 SDD：threshold-priority-rbac

§0一句話總則

越具體的設定越優先，命中即停，不疊加。
系統判斷某艘船、某個維度該用什麼閾值時，是「找到最貼近這艘船當下情境的那一層就用它」；各層的值不加總，同一維度同一時間只發一則事件。

「具體」有兩個方向：對象（針對這一艘船 ＞ 針對這片海域 ＞ 針對全船隊）與時間／航段（此刻有效的臨時設定 ＞ 常設；該航段專屬 ＞ 全航段通用）。兩者合起來就是下一節的八格查找順序。

§1層級與航段：需求規則圖

閾值分四層，由上到下越來越「通用」。每一層裡再分「該航段專屬」與「全航段通用」兩格。查找時先看層級、再看航段，所以編號 1 到 8 就是查找順序。

三條補充規則

欄位各自補齊。Warning、Critical、持續時間三個欄位是各自沿八格順序往下找的。單船覆寫可以只填 W 不填 C，沒填的 C 由下一層補上；來源標示因此可能是「W＝單船、C＝全船隊」。

通知與啟用開關比照分層。Mail／LINE 通知方式與「是否啟用偵測」使用同一套查找，但「啟用偵測」是目前介面缺的欄位，須新增；關閉時該維度顯示 N/A、不立案。

圍籬（到離區域）是船隊資產。圍籬本體只存在 L4；單船層只能「停用此船」或覆寫提醒距離與船速，不能刪除圍籬。全球唯讀風險區只顯示、不參與 L3。

§2判斷流程

每一輪資料更新（AIS、氣象、IoT 輪詢），對每艘船的每個維度跑一次下面的流程。閾值修改不觸發即時全船重算，等下一輪自然套用。

解析虛擬碼

resolve(vessel, dim, field, now):
  seg = stateMachine.segment(vessel)                 # sea | anchor | port
  layers = [ temporalVessel(vessel, now),            # L1  valid_from ≤ now ≤ valid_to
             vessel(vessel),                          # L2
             region(vessel.position),                 # L3  多區命中取風險最高者
             fleet() ]                                # L4
  for layer in layers:
    for s in [seg, "all"]:
      row = layer.find(segment=s, dimension=dim)
      if row and row[field] is not null:
        return { value: row[field], source: layer.name, segment: s }
  return { value: SYSTEM_DEFAULT[dim][field], source: "system", segment: "all" }

# field ∈ { enabled, warning, critical, warningDuration, criticalDuration, notifyMail, notifyLine }

§3角色與權限

誰管哪些船來自既有系統（只讀取、不維護）；能做什麼功能另用權限碼管理。判斷順序：先看功能權限碼 → 再看船舶指派（own／any）→ 才允許寫入對應層級。

角色可見範圍L4 全船隊L3 區域L2 單船常設L1 時效單船圍籬本體事件結案變更紀錄
系統管理員全部編輯編輯任一船任一船增刪改任一船全部
主管全部船、全部組員設定編輯編輯任一船任一船增刪改任一船全部
組員指派給自己的船唯讀唯讀自己的船自己的船唯讀，可停用此船自己的船自己的操作
代理（授權）被授權組員的船唯讀唯讀授權期間內授權期間內唯讀授權期間內自己的操作

權限碼建議：threshold.fleet.edit、threshold.region.edit、threshold.vessel.edit.own、threshold.vessel.edit.any、threshold.temporal.edit.own、threshold.temporal.edit.any、fence.fleet.manage、fence.vessel.toggle、event.resolve.own、event.resolve.any、audit.view.own、audit.view.all、vessel.view.all。角色是權限碼的預設組合，允許對個人加減。

目前 final 版的「代理檢視」是勾選即可編輯他人船舶。正式規則改為「代理」是一種可授權、有期限的權限（由主管或被代理人授權），不是自助勾選。

§4寫入與影響規則

  1. 明確儲存＋二次確認。不採自動儲存。確認框顯示：影響船數、其中因上層覆寫而「不受影響」的船數、生效航段。
  2. 改 L4 不動 L1～L3。主管修改全船隊預設，只有「沒有覆寫」的船跟著變。要讓全船隊統一，需另執行「清除覆寫」。
  3. 集體套用到「我的船」實為逐船寫入 L2。介面須明示「這將成為單船覆寫，之後不隨全船隊預設變動」。
  4. 時效覆寫（L1）必填有效起迄與事由。到期由系統自動失效並寫一筆變更紀錄（by system）。
  5. 同船多人指派時後寫者覆蓋，變更紀錄保留前值與前一位設定者。
  6. 每次寫入都留紀錄：who、when、layer、scope、segment、dimension、field、old、new、reason。
  7. 閾值變更不觸發即時重算；由下一輪資料週期套用。Demo 端的即時重繪只是畫面反映。

§5威明輪範例驗證

船在海上航段，航線偏移實際值 1.5 NM。全船隊預設海上航段 W≥1、C≥3。

情境命中格生效 W／C結果來源標示
無任何單船設定7 · L4 × 海上1 ／ 3WarningW＝全船隊·海上；C＝全船隊·海上
單船常設「海上航段」W≥23 · L2 × 海上2 ／ 3正常W＝單船·海上；C＝全船隊·海上
單船常設只設「全航段通用」W≥24 · L2 × 通用2 ／ 3正常W＝單船·通用；C＝全船隊·海上（單船通用仍先於全船隊專屬）
單船只填 C≥1.2，未填 WW→7　C→31 ／ 1.2CriticalW＝全船隊；C＝單船（欄位各自補齊）
軍演期間時效覆寫 W≥3（有效中）1 · L1 × 海上3 ／ 3 → 需 C>W，介面阻擋—驗證規則：Critical 必須大於 Warning
軍演期間時效覆寫 W≥2.5、C≥4（有效中）1 · L1 × 海上2.5 ／ 4正常W、C 皆＝時效·海上；到期後回到第二列
船進入台海軍演區，該區覆寫 W≥0.85 · L3 × 海上0.8 ／ 3WarningW＝區域；若同時有單船設定則單船優先，區域不生效

§6最小可行介面流程（MVP）

目標是用最少的畫面讓組員「看得懂目前生效的是哪一層」、「改自己的船不會誤傷別人」，讓主管「改全船隊前知道影響誰」。三個畫面、兩條流程。

三個畫面的最小內容

畫面 A · 分航段集體設定（主管）

  • MVP 範圍：全船隊預設 ／ 依組員的船隊（後者明示「寫入單船覆寫」）
  • MVP 航段分頁：海上／錨泊漂流／進出港／全航段通用
  • MVP 套用前 confirm：影響 N 艘、M 艘不受影響、生效航段
  • MVP 修正「依組員的船隊」套用無效的既有 bug
  • 後續 區域覆寫（L3）編輯入口（目前無 UI）

畫面 B · 單船設定（組員／主管）

  • MVP 每維度一列：生效 W／C／持續時間 ＋ 來源徽章（L1–L4 × 航段）
  • MVP 覆寫類型切換：常設 ／ 時效（起迄、事由必填）
  • MVP 改為明確「儲存」，不再 blur 即存
  • MVP 圍籬列：只有「停用此船」與覆寫距離／船速，無刪除
  • 後續 啟用偵測開關（需先新增欄位）

畫面 C · 變更紀錄

  • MVP 列表：時間、操作者、層級、對象、維度、舊值→新值、事由
  • MVP 組員只看自己的操作；主管可依組員篩選
  • MVP 時效到期由系統寫入一筆
  • 後續 匯出、還原到某一筆

共用

  • MVP 帳號帶角色：系統管理員／主管／組員；組員看不到 L4／L3 的編輯控制
  • MVP 船舶詳情頁的警示表也顯示來源徽章，讓「為什麼這艘船沒警報」一眼可查
  • 後續 代理授權（有期限）取代「代理檢視」勾選

§7與 final 版的落差摘要

項目final 現況本規範
層級單船 ＞ 區域 ＞ 全船隊（三層）；僅航線偏移、速度可單船覆寫時效單船 ＞ 單船 ＞ 區域 ＞ 全船隊（四層）；所有可設維度皆可覆寫
航段只存欄位，不參與判斷；海上與通用寫同一值該航段專屬 ＞ 全航段通用，參與判斷
時效設定無L1，起迄＋事由，到期自動失效
儲存方式集體設定有套用＋confirm；單船 blur 即存一律明確儲存＋影響預覽
權限isAdmin 二分；代理檢視勾選即可編輯他人船角色 × 權限碼；代理為有期限授權
圍籬單一份，單船頁可刪、影響全船隊船隊層資產；單船只能停用／覆寫
變更紀錄無（事件有 history）每次寫入必留
既有 bug主管「依監管人員的船隊」套用無任何寫入MVP 一併修正

final 版依專案鐵則不修改；以上調整只做在 merged 版。實作順序建議：先做規則（來源徽章、八格查找、時效層、影響預覽、既有 bug），再做權限與紀錄。
