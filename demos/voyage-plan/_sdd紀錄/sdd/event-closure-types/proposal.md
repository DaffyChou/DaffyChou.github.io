# proposal：event-closure-types（警報解除的兩種結案：條件消失 vs 人為處理）

日期：2026-09-17　狀態：待確認　來源：客戶 Q&A 第 14 題 ＋ 使用者補充

## 需求
警報解除後紀錄必須保留，並明確分成兩種：
- **觸發條件已消失**（系統自動）：例如航線回到計畫內、速度回正常、海況降、主機回正常、離開區域。
- **人為處理**（監管人員／代理人／主管結案）：有人看過、處理過並標記解決。
兩種都是「已結束」，但要能分開看、分開統計；一筆事件可能同時具備兩者（先人為處理、後來條件也消失，或反之），兩個時間點都要留。

## 目前
`cleared`（條件消失）是旗標，與流程狀態（新立案／處理中／已解決）並存；列表用徽章顯示「警報已解除」，但沒有把兩種結案並列成可篩選、可統計的狀態，也沒有記錄條件消失的時間。

## 變更
- 資料：事件加 `clearedAt`（條件消失時間，系統寫）、`resolvedAt`／`resolvedBy`（人為結案時間與人）；`cleared` 保留。
- 狀態顯示（三種）：進行中（新立案／處理中）、**條件已消失**（系統，cleared 且未人為結案）、**人為處理**（resolved）。列表徽章與篩選 tab 對應這三種；統計卡分開計數。人為處理那筆若條件也已消失，只在徽章加小註「·條件已消失」與詳情時間軸顯示，不另成一類（2026-09-17 使用者確認）。
- 行為：條件消失後**不自動變已解決**，仍可由人標記解決（留誰處理）；已解決後條件再度發生 → 新立一筆（不重開舊筆），舊筆保留。
- 條件消失後若條件再度出現且舊筆仍未人為結案 → 同一筆恢復「進行中」並記錄「再度觸發 N 次」。
- 事件詳情：時間軸顯示「立案 → 條件消失 → 人為處理」各時間；報表／匯出含兩欄。
- 各維度的「條件消失」定義：航線回到 W 內、速度回配速比例內、海況指數低於 W、主機分數低於 W、離開圍籬／港區、漂航／錨泊回圈內、目的地一致；持續時間規則同立案（避免抖動）。

## 不做
- 不自動結案；不刪除任何紀錄。

## 待確認（訪談）
① 「條件已消失但未人為處理」是否要在 N 天後自動歸檔（不是結案，只是不再列在待辦）；② 客戶是否接受「不自動已解決」。
